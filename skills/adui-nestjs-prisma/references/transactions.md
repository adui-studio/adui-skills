# 事务规范

[简体中文](./transactions.md) | [English](./transactions.en.md)

## 什么时候需要事务

当多个数据库动作必须作为一个业务原子操作一起成功或失败时评估事务，例如：

- 主记录与必须同步写入的关联记录。
- 库存扣减与数据库内订单状态变更。
- 多表一致性更新。

单条原子 SQL/Prisma 操作已经满足需求时，不为了形式额外包事务。

## 事务边界

- 事务围绕业务用例，而不是围绕 Controller 或任意 Service 方法。
- 事务内只放必须受同一数据库原子性保护的工作。
- 避免事务中执行远程 HTTP、MQ 等不可回滚外部副作用。
- 避免长时间计算、等待和日志上传导致锁持有时间过长。
- 对重试、隔离级别和并发冲突只在真实场景需要时增加复杂度。

## 外部副作用

数据库事务无法回滚已经发出的 HTTP 请求、消息或文件写入。需要可靠一致性时评估 Outbox、幂等、补偿或任务表，而不是扩大数据库事务假装覆盖外部系统。
