# ADui 编程任务交付格式

默认按以下顺序组织最终回复。简单任务可以压缩篇幅，但不要打乱核心顺序。

## 1. 需求与约束

简要复述：

- 要解决的问题。
- 关键输入/输出。
- 不允许改变的行为。
- 验收目标。

## 2. 假设与风险

只写实际存在的内容：

- 必要假设。
- 兼容性风险。
- 安全风险。
- 数据/迁移风险。
- 仍缺少但不阻塞的信息。

没有则写“无额外关键假设”。

## 3. 解决方案与代码

- 说明核心思路。
- 用户要求完整代码时提供完整代码；修改现有仓库时优先给准确 diff/修改后的文件，不无故扩大范围。
- 不声称未实际执行的结果。

## 4. 修改位置与原因

说明：

```text
文件/模块 → 修改内容 → 修改原因 → 可能影响
```

## 5. 运行与验证

明确区分：

- 已执行且通过。
- 已执行但失败。
- 当前环境无法执行，提供用户可运行的命令。

示例：

```text
已执行
- npm run lint ✅
- npm run test ✅
- npm run build ✅

未执行
- 真机微信小程序验证：当前环境无微信开发者工具
```

## 6. 仍未确认的问题

只列真实未确认项。不要为了完整格式虚构问题。

## Git 建议（需要时）

可附建议：

```text
feat(module): 中文提交说明
fix(module): 中文提交说明
```

除非用户明确要求，否则不自动执行 commit/push/merge/release。
