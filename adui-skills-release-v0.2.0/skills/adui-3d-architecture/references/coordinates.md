# 坐标体系与精度

[简体中文](./coordinates.md) | [English](./coordinates.en.md)

## 原则

- 明确区分业务坐标、地理坐标、引擎世界坐标和屏幕坐标。
- CesiumJS 场景通常围绕椭球、Cartographic 与 Cartesian3 工作；涉及地球场景时记录采用的椭球和高度基准。
- Three.js / Babylon.js 通常使用局部笛卡尔坐标。把地理数据送入本地引擎前先建立局部参考系，例如 ENU 或项目定义的局部原点。
- 大尺度场景使用局部原点、origin rebasing、分块或引擎提供的高精度机制，避免把超大世界坐标直接塞进单精度 GPU 计算。

## 必须记录

1. 输入 CRS / EPSG 或业务坐标定义。
2. 经度、纬度、X、Y、Z 的轴顺序和单位。
3. 高程基准与单位。
4. 本地原点及其地理位置。
5. 地理坐标到渲染坐标的唯一转换入口。
6. 模型自身坐标系、轴向和缩放。

## 多引擎

不要在多个引擎中各自实现一份坐标转换。建立独立 `spatial`/`geo` 适配层，渲染层只消费明确的数据结构。

路径规划、碰撞图、NavMesh 和灾害权重使用统一空间数据模型，不依赖 Three.js、Babylon.js 或 CesiumJS 的对象实例作为核心数据结构。
